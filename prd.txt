# Ticketing App with Time Tracking - Product Requirements Document (PRD)

## 📋 Document Information
- **Product Name**: Ticketing App with Time Tracking
- **Version**: 1.0 (MVP)
- **Date**: [Current Date]
- **Author**: Engineering Team
- **Status**: Draft

## 🎯 Executive Summary

### Product Vision
A streamlined ticketing system with integrated time tracking capabilities that enables teams to efficiently manage projects, track issues, and monitor time spent on tasks. The MVP focuses on core functionality that delivers immediate value to users.

### Target Users
- **Primary**: Project managers and team leads
- **Secondary**: Developers and team members
- **Tertiary**: Stakeholders and clients

### Success Criteria
- Users can create and manage projects within 30 seconds
- Ticket creation takes less than 1 minute
- Time tracking is accurate and easy to use
- Dashboard provides actionable insights
- System handles 100+ concurrent users

## 🛠️ Technical Stack
- **Frontend**: Next.js 14+ (App Router)
- **Backend**: Supabase (PostgreSQL + Auth + Real-time)
- **State Management**: Zustand
- **UI Framework**: shadcn/ui + Tailwind CSS
- **Language**: TypeScript
- **Deployment**: Vercel

## 🏢 Multi-Tenancy Structure
- The system is multi-tenant: each company's data is isolated.
- Users, projects, and tickets are always scoped to a company.

## 📊 MVP Scope

### ✅ Included in MVP
- User authentication and basic profile management
- Project creation and management
- Ticket creation, assignment, and status management
- Basic time tracking (start/stop timer)
- Simple dashboard with key metrics
- Basic search and filtering
- User role management (Admin, Manager, User)

### ❌ Excluded from MVP (Future Releases)
- Advanced reporting and analytics
- File attachments
- Custom workflows
- Email notifications
- API integrations
- Mobile app
- Advanced time reports
- Real-time notifications

## 🎯 Core Features Requirements

## 0. Company Management

### 0.1 Company Creation & Management
**Requirement**: The system must support multiple companies, each with its own users and projects.

**Functional Requirements**:
- First user creates a company on signup
- Admins can manage company info (name, settings)
- Admins can invite/manage users in their company
- Users can only belong to one company (MVP)
- Company selection/join flow for users

**Technical Requirements**:
- Company data stored in companies table
- Enforce company-level data isolation (RLS)
- All queries scoped to company_id

**Acceptance Criteria**:
- [ ] User can create a company
- [ ] Admin can update company info
- [ ] Admin can invite/manage users
- [ ] Users can only see their company's data

## 1. User Authentication & Management

### 1.1 User Registration & Login
**Requirement**: Users must be able to register and login securely.

**Functional Requirements**:
- Users can register with email and password
- Users can login with email and password
- Users can reset their password via email
- Users can logout from any page
- Session persistence across browser sessions
- User must join or create a company on signup

**Technical Requirements**:
- Use Supabase Auth for authentication
- Implement proper password validation (min 8 chars, complexity)
- Store user sessions securely
- Handle authentication errors gracefully
- Users table includes company_id foreign key
- All user queries scoped to company_id

**Acceptance Criteria**:
- [ ] User can register with valid email and password
- [ ] User can login with correct credentials
- [ ] User receives password reset email
- [ ] User session persists after browser refresh
- [ ] User can logout successfully
- [ ] User is always associated with a company
- [ ] User cannot access data from other companies

### 1.2 User Profile Management
**Requirement**: Users can view and edit their profile information.

**Functional Requirements**:
- Users can view their profile information
- Users can edit their name, email, and avatar
- Users can change their password
- Profile changes are saved immediately

**Technical Requirements**:
- Profile data stored in Supabase users table
- Avatar upload to Supabase storage
- Real-time profile updates

**Acceptance Criteria**:
- [ ] User can view their profile information
- [ ] User can edit profile fields
- [ ] Changes are saved and reflected immediately
- [ ] Avatar upload works correctly

### 1.3 User Roles & Permissions
**Requirement**: System supports three user roles with different permissions.

**Functional Requirements**:
- **Admin**: Can manage all projects, users, and system settings
- **Manager**: Can manage assigned projects and tickets
- **User**: Can view assigned projects and create/manage assigned tickets

**Technical Requirements**:
- Role-based access control (RBAC)
- Supabase Row Level Security (RLS) policies
- Role validation on all API endpoints

**Acceptance Criteria**:
- [ ] Admin can access all features
- [ ] Manager can manage assigned projects
- [ ] User can only access assigned content
- [ ] Role changes are reflected immediately

## 2. Project Management

### 2.1 Project Creation
**Requirement**: Users can create new projects with essential information.

**Functional Requirements**:
- Users can create projects with name, description, and status
- Projects are assigned to the creating user by default
- Project creation is immediate and requires minimal input
- Project must be created within a company

**Technical Requirements**:
- Project data stored in Supabase projects table
- Real-time project creation
- Optimistic updates for better UX
- Projects table includes company_id foreign key
- All project queries scoped to company_id

**Data Model**:
```sql
projects {
  id: uuid (primary key)
  name: text (required)
  description: text
  status: enum ('active', 'archived', 'completed')
  company_id: uuid (foreign key to companies)
  created_by: uuid (foreign key to users)
  created_at: timestamp
  updated_at: timestamp
}
```

**Acceptance Criteria**:
- [ ] User can create project with required fields
- [ ] Project appears in list immediately
- [ ] Project is assigned to creating user
- [ ] Validation prevents empty project names
- [ ] Project is always associated with a company
- [ ] Project cannot be moved between companies (MVP)

### 2.2 Project Listing & Management
**Requirement**: Users can view and manage their projects.

**Functional Requirements**:
- Users can view list of projects they have access to
- Users can edit project details
- Users can archive/complete projects
- Projects are sorted by recent activity
- Search and filter projects by name/status

**Technical Requirements**:
- Pagination for large project lists
- Real-time updates when projects change
- Efficient querying with proper indexing

**Acceptance Criteria**:
- [ ] User can view their projects
- [ ] User can edit project details
- [ ] User can change project status

- [ ] List updates in real-time

## 3. Ticket Management

### 3.1 Ticket Creation
**Requirement**: Users can create tickets within projects.

**Functional Requirements**:
- Users can create tickets with title, description, and priority
- Tickets are assigned to a specific project
- Tickets can be assigned to team members
- Ticket creation is quick and intuitive
- Ticket must be created within a project

**Technical Requirements**:
- Ticket data stored in Supabase tickets table
- Real-time ticket creation
- Optimistic updates
- Tickets table includes project_id foreign key
- All ticket queries scoped to project_id (and thus company)

**Data Model**:
```sql
tickets {
  id: uuid (primary key)
  title: text (required)
  description: text
  status: enum ('new', 'in_progress', 'review', 'done')
  priority: enum ('low', 'medium', 'high', 'critical')
  project_id: uuid (foreign key to projects)
  assigned_to: uuid (foreign key to users)
  created_by: uuid (foreign key to users)
  created_at: timestamp
  updated_at: timestamp
}
```

**Acceptance Criteria**:
- [ ] User can create ticket with required fields
- [ ] Ticket is assigned to correct project
- [ ] Ticket can be assigned to team member
- [ ] Ticket appears in list immediately
- [ ] Ticket is always associated with a project
- [ ] Ticket cannot be moved between projects (MVP)

### 3.2 Ticket Management & Workflow
**Requirement**: Users can manage tickets through a defined workflow.

**Functional Requirements**:

- Users can update ticket status
- Users can edit ticket details
- Users can add comments to tickets
- Ticket history is tracked

**Technical Requirements**:

**Acceptance Criteria**:

- [ ] User can edit ticket details

- [ ] Ticket history is maintained

### 3.3 Ticket Listing & Search
**Requirement**: Users can view and search tickets efficiently.

**Functional Requirements**:

## 4. Time Tracking

### 4.1 Timer Functionality
**Requirement**: Users can track time spent on tickets using a timer.

**Functional Requirements**:
- Users can start/stop timer for specific tickets
- Timer shows elapsed time in real-time
- Users can pause and resume timer
- Timer data is saved automatically
- Only one timer can be active per user

**Technical Requirements**:
- Timer state managed in Zustand store
- Real-time timer updates
- Automatic time entry creation
- Browser storage for timer persistence

**Data Model**:
```sql
time_entries {
  id: uuid (primary key)
  ticket_id: uuid (foreign key to tickets)
  user_id: uuid (foreign key to users)
  start_time: timestamp
  end_time: timestamp
  duration: interval
  description: text
  created_at: timestamp
}
```

**Acceptance Criteria**:
- [ ] User can start timer for ticket
- [ ] Timer shows elapsed time accurately
- [ ] User can stop timer
- [ ] Time entry is saved automatically
- [ ] Only one timer active per user

### 4.2 Time Entry Management
**Requirement**: Users can view and manage their time entries.

**Functional Requirements**:
- Users can view time entries by ticket
- Users can edit time entry descriptions
- Users can delete time entries
- Time entries show duration and date
- Time entries are sorted by date

**Technical Requirements**:
- Time entry CRUD operations
- Duration calculations
- Real-time updates

**Acceptance Criteria**:
- [ ] User can view time entries
